# История изменений

Все существенные изменения этого проекта документируются в этом файле.

## v2.3.1

### Исправлено

- Пример автоматизации для триггера поверки счётчика.
- Предупреждение о нехватке данных при обработке пустого списка счётчиков больше не записывается в журнал событий.

## v2.3.0

### Добавлено

- Событие о приближении даты поверки активного счётчика, отправляемое один раз для каждой даты поверки.

### Исправлено

- Отсутствующий атрибут `is_archived` в сенсорах счётчиков.
- Внутренние исправления кода.

## v2.2.0

### Добавлено

- Сенсоры архивных счётчиков: новые сущности отключены по умолчанию и отмечены значком архива.

## v2.1.1

### Изменено

- Атрибут `name` счётчика содержит переведённое имя сенсора; исходное название счётчика перенесено в `meter_name`.
- Атрибут `name` сенсора управляющей компании содержит переведённое имя сенсора.

## v2.1.0

### Добавлено

- Диагностические сенсоры с формулами расчёта суммарных тарифов воды для каждого лицевого счёта.

### Исправлено

- При открытии настроек до загрузки интеграции показывается предложение повторить попытку позже вместо ошибки.
- Атрибут `name` сенсоров суммарных тарифов и их формул содержит переведённое имя.
- Описание настройки суммарных тарифов в README.

## v2.0.0

### Добавлено

- Поддержка нескольких адресов одной учётной записи: для каждого лицевого счёта создаётся отдельное устройство с сенсорами.
- Форма настройки суммарных тарифов и норматива подогрева.

### Изменено

- Суммарные тарифы рассчитываются по выбранным для каждого счёта тарифам; прежний автоматический выбор необходимо настроить заново.
- Норматив подогрева воды настраивается отдельно для каждого лицевого счёта в параметрах интеграции. Прежний общий норматив необходимо задать заново.
- При добавлении и перенастройке интеграции запрашиваются только логин и пароль.
- Настройки прежних версий несовместимы с новой версией интеграции; настройте интеграцию заново.
- При переключении с автоматического норматива подогрева воды на ручной подставляется рассчитанное значение.
- Сенсоры счётчиков и тарифов одной записи интеграции объединены в устройство.
- В названии устройства отображаются номер лицевого счёта и адрес.
- Идентификаторы устройств и сенсоров включают номер лицевого счёта; ранее созданные устройства и сущности могут потребовать повторной настройки.

### Исправлено

- Исправлено падение тестов в GitHub Actions из-за несовместимости зависимостей DNS.

## v1.1.0

### Добавлено

- Перенастройка имени пользователя и пароля без удаления записи интеграции.
- Настройка норматива расхода тепловой энергии на подогрев воды в параметрах интеграции.
- Автоматический суммарный тариф для холодной воды (холодная вода + водоотведение).
- Автоматический суммарный тариф для горячей воды (горячая вода + водоотведение, либо теплоноситель + подогрев * на коэффициент + водоотведение).

### Изменено

- Обновлён раздел подсчёта трат по счётчикам в README на русском и английском языках.

## v1.0.5

- Неправильные ссылки и название репозитория после переименования в `hass-zkhnso`.

## v1.0.0

### Добавлено

- Описание создания шаблона сенсора и таблица коээфициентов для подогрева теплоносителя.
